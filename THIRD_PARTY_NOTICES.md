# Third-party notices

Stow is licensed under MIT OR Apache-2.0 (`LICENSE-MIT`, `LICENSE-APACHE`). It bundles or statically links third-party work that keeps its own license. This file is the short, hand-maintained summary; the complete list with full license texts is **`THIRD_PARTY_LICENSES.md`**, generated by `scripts/collect-licenses.sh` (`just licenses`) from `Cargo.lock` (cargo-about) and `apps/stow-app/node_modules` (`npm ls --omit=dev`) and committed to the repository. CI (`scripts/collect-licenses.sh --check`) fails when it is stale.

## How the notices are delivered

| Download | Where the notices are |
|---|---|
| `Stow.app` (DMG) | `THIRD_PARTY_NOTICES.md` and `THIRD_PARTY_LICENSES.md` are bundled into `Stow.app/Contents/Resources/` via `bundle.resources` in `apps/stow-app/src-tauri/tauri.conf.json`. `release.yml` fails the release if either file is missing from the built app. |
| `stow-cli_<v>_aarch64-apple-darwin.tar.gz` (`stw`) | The tarball contains `stw`, Stow's `LICENSE*` files, `THIRD_PARTY_NOTICES.md`, and `THIRD_PARTY_LICENSES.md` (the "Build CLI" step in `.github/workflows/release.yml`). |
| Chrome extension zip | Contains no third-party code; nothing to deliver. |
| Source | Both files at the repository root. |

Attribution for Font Awesome's CC BY 4.0 icons is delivered through these two files. The app imports individual SVG icons from `@fortawesome/free-*-svg-icons`, which carry no CSS license header, so there is no header to preserve in the built bundle.

## Keeping this current

- Adding or bumping a dependency: run `just licenses` and commit `THIRD_PARTY_LICENSES.md` with the lockfile change. The allow-lists in `deny.toml` (`[licenses].allow`) and `scripts/licenses/about.toml` (`accepted`) must agree.
- Adding a new bundled asset (font, icon set, model) or a new native library: add a row here as well.
